## 4. IA Local (DocIntel) — smoke + latência — #76, #80

**Smoke real end-to-end** rodado de **dentro do `importacao-api`** (caminho de
produção, na rede `ia-local-net`): `/v1/models` ✅ (~185ms), geração com contrato
estrito `ok=true,ncm=85044010` ✅ (~154s), embeddings 1024-dim ✅ (~94s).

**Causa raiz da latência (medida, não é bug):** servidor com **12 GiB RAM** +
Ollama carrega `--no-mmap` (lê os 3,3GB do disco p/ RAM) + keep_alive curto →
o modelo descarrega/recarrega a cada inferência. 1ª carga fria > 180s (chega a
abortar o load); recarga com arquivo em page-cache ~40s.

**Decisão (Nicolas): NÃO teremos GPU.** O VLM de visão (qwen3-vl) está
descartado. Estado permanente = **parsers determinísticos primeiro** + LLM de
texto local (`unico-docintel`, base qwen2.5:3b, assíncrono no worker) como
reforço. Issue **#80 fechada** (not planned). Alavanca de tuning sem GPU: subir
`OLLAMA_KEEP_ALIVE` para manter o modelo residente entre extrações.

## 5. cert-api: 500 no export de reports — #85 (corrigido)

**Sintoma:** `GET /cert-api/api/reports/validation_*.json?format=xlsx` → 500
`PermissionError: Permission denied: '/app/reports/...xlsx'`.

**Causa raiz:** drift de uid. O cert-api roda como `appuser` **uid 1001** (pinado
no Dockerfile), mas o volume `importacao_cert-reports` foi criado quando o uid
era 999 (dir `999:999 mode 755`). Os `validation_*.json` são escritos pelo
`importacao-api` como **root** (root ignora permissão), por isso só a escrita do
cert-api quebrava.

**Fix aplicado ao vivo (durável):**

```bash
docker run --rm -v importacao_cert-reports:/data alpine chown -R 1001:1001 /data
```

Durável porque o Dockerfile pina uid 1001. **Verificado:** o endpoint exato
voltou **200** com XLSX válido (47289 bytes, magic `PK`). Hardening opcional
(streamar o XLSX derivado de `BytesIO` em vez de persistir no volume) registrado
em #85.

## 7. Análise profunda da extração (2026-06-16)

Investigação do DEMO real no banco de produção. **Os 5 documentos foram
extraídos** (chaves reais: `invoice, packing_list, ohbl, draft_bl, espelho` —
correção: chaves são snake_case, não `packingList`/`bl`). O problema **não** é
documento faltando nem feature ausente:

| Documento    | Itens | Campos de cruzamento                                   |
| ------------ | ----- | ------------------------------------------------------ |
| invoice      | 7 ✅  | exporterName / invoiceDate / portOfLoading = **nulos** |
| packing_list | 7 ✅  | sem campos de porto; `date` nula                       |
| ohbl (BL)    | —     | campos existem, **valores nulos**                      |

**Raiz isolada:** acurácia de extração do **modelo local** (`unico-docintel` /
qwen2.5:3b, CPU) em cabeçalho/portos/datas. O comparativo e as features funcionam
**quando os campos são extraídos**. Os sintomas 7/10/11 do cliente são todos
isso.

**Recomendação técnica (privacidade × qualidade):** tunar o modelo local fraco
tem teto baixo (sem GPU). O ponto ótimo é **mover a extração para o Vertex AI
(Gemini no Vertex)** — extração forte **+ no-training contratual** (dado não usado
para treino), satisfazendo privacidade E qualidade, ao contrário da Developer API
(treina no free tier) e do local (fraco). Bloqueio: IAM (#60). Sugestão:
`AI_PROVIDER=vertex` + `AI_ALLOW_EXTERNAL=true` para extração, `ialocal` como
fallback.

### Certificação — SKU 050402313 (corrigido ao vivo)

"Caneta com LED Dino": estava `site_status=NAO_CONFORME` com
`last_validation_status=EXPIRED` defasado. Revalidação (`POST
/api/products/verify`) re-varreu o VTEX → `URL_NOT_FOUND` (produto saiu do site)
→ **site_status: NAO_CONFORME → CONFORME**. A lógica de derivação estava
correta; era dado defasado. **Fix sistêmico:** agendar revalidação periódica
(`POST /api/validate`) — a defasagem afeta outros SKUs.

## 8. Decisões pendentes (precisam do Nicolas)

Itens onde adivinhar seria irresponsável (regulatório / privacidade / negócio):

1. **Extração: Vertex vs local** (#76) — privacidade × qualidade. Recomendação:
   desbloquear Vertex (#60) e usar para extração. **É a alavanca de maior
   impacto** nos sintomas do demo.
2. **Cert "Licen. - Prazo"** (#87) — a planilha (aba "Encerramentos") só tem
   **UM** prazo (`prazo final venda`). Não existe prazo de licenciamento
   separado. Decidir: (a) planilha passa a ter prazo de licenciamento próprio,
   ou (b) cert e licenciamento compartilham o mesmo prazo. O mapeamento "qual
   órgão é certificação vs licenciamento" é regulatório — não deve ser chutado.
3. **Estoque × WMS** (#87) — coluna "CD" usa **DISPONÍVEL** do Oracle WMS (não
   físico); "E-com" vem do SQL Server ERP. Definir disponível × físico.
4. **Comunicações + Emails** (#87) — são SAÍDA (compor/enviar) vs ENTRADA (robô
   lê mailbox → vira documento). Decisão de UX: unificar numa view só?
5. **Variáveis de e-mail** ausentes em prod: `KIOM_EMAIL`, `FENICIA_EMAIL`,
   `ISA_EMAIL` (#78).
